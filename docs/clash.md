# Clash 共存说明：直连规则文件是什么、要不要用

> 结论先行：**只开「系统代理」时不需要配置任何规则**，工具自身就能绕过 Clash 完成认证；**开「TUN 模式」时才需要**最小直连规则（或完整规则文件）。

## 一、三种使用姿势对照

| Clash 工作模式 | 不配规则能否自动登录 | 说明 |
|---|---|---|
| 不开 Clash | ✅ 可以 | 基线场景 |
| 仅系统代理（不开 TUN） | ✅ 可以 | 工具请求强制直连，完全绕开 Clash |
| TUN 模式 | ❌ 不行（或不稳） | 流量在 IP 层被 TUN 接管，需直连规则兜底 |

## 二、为什么系统代理模式能绕过

Clash 的「系统代理」只影响**读取系统代理设置的程序**（浏览器、多数桌面应用）。本工具的探测与登录请求在代码层显式清空了全部代理配置（等价于 `curl --noproxy *` / `requests(trust_env=False)`），永远从物理网卡直达认证服务器 `202.196.169.166`，与 Clash 开不开无关。

这是方案中的「第二层防线」：**程序强制直连**。即使规则一条不配，自动登录本身也是通的。

## 三、TUN 模式为什么不行

TUN 在 **IP 层**接管全机流量：

1. 工具的"直连"请求也会被截进 mihomo 的虚拟网卡，由规则决定走向；认证服务器 IP 一旦被匹配到 `PROXY`，登录请求就绕道境外节点，必然失败。
2. TUN 通常伴随 `dns-hijack` + fake-ip，探测域名 `www.msftconnecttest.com` 的解析被干扰，探测结果失真。
3. 系统的联网探测（NCSI）同样被截获，"认证页自动弹出"失效——不过工具自己探测，不依赖弹出。

### 最小规则（只求认证可用）

```yaml
rules:
  - IP-CIDR,202.196.169.166/32,DIRECT,no-resolve   # 认证服务器
  - IP-CIDR,10.0.0.0/8,DIRECT,no-resolve           # 覆盖 wlanacip=10.0.1.10
tun:
  route-exclude-address:
    - 202.196.169.166/32                           # 认证流量不进 TUN
    - 10.0.0.0/8
```

### 完整规则（认证页 + 系统探测都正常）

点工具界面的**「生成 Clash 直连规则文件」**，得到 `clash_campus_direct.yaml`，包含三段：

| 段落 | 作用 |
|---|---|
| `dns.fake-ip-filter` | 让连通性检测域名返回真实 IP，系统能正确判定"未认证" |
| `rules`（DIRECT） | 认证服务器、私网段、探测域名全部直连 |
| `tun.route-exclude-address` | 认证网段不进虚拟网卡（仅 TUN 模式需要） |

## 四、怎么合并进 Clash

**方式 A：直接改配置文件**
1. 打开 mihomo 配置（`config.yaml`）
2. 把 `rules:` 下的几行粘到**原有规则列表最前面**（必须在 `MATCH,PROXY` 等兜底规则之前，否则永远匹配不到）
3. 把 `fake-ip-filter` 几项并入现有 `dns.fake-ip-filter`
4. TUN 模式再合并 `tun.route-exclude-address`
5. 重载配置 / 重启内核

**方式 B：客户端的 Merge / 覆写功能（推荐）**
- **Clash Verge Rev / Mihomo Party**：新建 Merge 或全局扩展配置，粘贴文件内容并关联订阅——订阅更新不会冲掉规则
- **Clash for Windows**：Profiles → 右键 → Merge

**方式 C：什么都不配**
系统代理模式下可用；浏览器里手动打开认证页可能仍被挡，但工具自动登录不受影响。

## 五、验证

1. 重载 Clash 后断开 WiFi 再重连
2. 看工具日志区：应出现 `LOGGING_IN → 复测结果：ONLINE`（约 5–10 秒）
3. 或命令行 `python campus_login.py --check`：返回 `ONLINE` 或带 `webauth.do` 的重定向即链路正常

## 常见问题

| 现象 | 处理 |
|---|---|
| 关掉 Clash 能登录、开着就失败 | 多半是 TUN 模式，补最小规则 |
| 只开系统代理也失败 | 把日志区内容发 issue，附 `--diag` 输出 |
| 规则加了没生效 | 检查是否放在 `MATCH` 兜底规则**之前**；确认已重载配置 |
| 订阅更新后又失效 | 用方式 B（Merge/覆写），不要直接改订阅文件 |
